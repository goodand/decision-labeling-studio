## 역할 분담 (2026-11-03 사용자 결정)
- **대부분의 로직은 에이전트가 직접 만든다.** 질의 정규화, 대조 규칙, 검색 전략은 ldx가 미리 넣지 않는다. 에이전트에게는 안전한 데이터 접근(등록·스캔·읽기 전용 SQL·결과 봉투)만 준다.
- **ldx의 핵심 가치는 사람이 원하는 GUI와 호환되는 것이다.** 사본·변환 결과는 표준 SQLite로 두어 사람이 고른 GUI가 그대로 열 수 있게 한다.
- 따라서 Kiwi(형태소)는 최소 구성에서 빼고 확장 자리로 옮긴다. 근거: 실제 검색 두 건("안전장치", "패션 디자인 시제품")은 Kiwi 없이 단어별 trigram/LIKE로 찾아짐(2026-11-03 실측). Kiwi가 필요한 조사·붙여쓰기 질의는 실제 요청에 없었다.
- **A12 변경 기록:** "조사·띄어쓰기가 다른 한글 질의" 조건을 확장 단계 속성으로 내림. 사유: 실제 요청에 없음, 질의를 쓰는 에이전트가 정규화할 수 있음. 셀 안 문장의 일부 단어·모든 시트·코드·숫자 질의 조건은 유지.

## 설계 범위와 구현 범위 (2026-11-03 원칙)
- **설계**는 SC1~SC7, A01~A17 전체와 확장 지점(어댑터·명령·검색기 교체)을 고려한다.
- **구현**은 기능을 줄이지 않는다. SC1~SC7을 모두 만들되, 기능마다 그 기능이 돌아가는 데 필요한 **최소 구성**만 짠다. 구성을 더할지는 써 보면서 드러난 부족분으로 판단한다.
- 원본 불변(A01~A03)은 모든 기능의 최소 구성에 들어간다(사고 비용이 큼).

### 최소 구성도 재사용 코드로 (2026-11-03 원칙)
다른 사람이 만들어 실제로 돌아가는 repo·라이브러리를 쓰면 검증 비용이 준다. 기능마다 직접 짜는 코드보다 재사용을 먼저 찾고, 직접 짜는 부분은 둘을 잇는 접착 코드로 한정한다. 아래 후보는 모두 "이 PC에서 실행 확인 전"이며, 채택 전 합성 파일로 실행해 본다.

| 기능 | 재사용 후보 | 직접 짜는 부분 |
|---|---|---|
| 원본 불변(SQLite) | Datasette의 immutable 모드(`datasette -i`), 표준 sqlite3 `immutable=1` | 부속 파일 판별 → 스냅샷 복사 |
| 엑셀·CSV 읽기 | python-calamine, DuckDB `read_csv`(인코딩 지정) | 시트 목록을 카탈로그 행으로 |
| 등록·스캔·카탈로그 | DuckLocal의 소스 등록·카탈로그 패턴, sqlite-utils(엑셀→`.ldx` 안 SQLite 변환) | 변경 판별 (size, mtime_ns) |
| 결과 봉투·JSON API | Datasette JSON API(`_size`, `truncated`, `next`) | `limitations`·`read_completeness` 추가 |
| 읽기 전용 SQL | Datasette의 SELECT 전용 실행, DuckDB `json_serialize_sql` | 문장 수·CTE 검사 |
| 셀 검색 | kiwipiepy + bm25s, (대안) Datasette `sqlite-fts`/FTS5 | 열 안 고유값 묶기 |
| GUI | Datasette 웹 화면(테이블 보기·검색·SQL) + 플러그인 | 대조 화면 플러그인 하나 |
| CLI | typer, Datasette·sqlite-utils CLI | `ldx` 명령 묶음 |

다음 확인: Datasette가 위 기능 중 몇 개를 실제로 덮는지 합성 파일로 실행 실측.
