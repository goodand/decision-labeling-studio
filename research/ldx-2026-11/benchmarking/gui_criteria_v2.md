## 결론 (v1과 다른 점)
1. v1 1위 Datasette(77)는 GUI 기준에서 **49점, 3위**. 1위는 사용자가 이미 만들어 승인한 **decision-labeling-studio(82)**, 2위는 **엑셀(63)**.
2. 사람이 원하는 GUI는 하나가 아니라 **엑셀(보기·편집) + studio(대조·검수)** 두 개다. 두 GUI가 서로 못 하는 것을 보완한다(엑셀 G2·G3 약함, studio G1 약함).
3. 따라서 ldx의 GUI 호환 목표는 "자체 화면"이 아니라 **두 GUI가 먹는 파일을 만드는 것**이다:
   - 엑셀용: 식별열 틀 고정·출처 열을 갖춘 xlsx/CSV 내보내기, 사람이 고친 xlsx를 그대로 읽기(SC1).
   - studio용: 질의·대조 결과를 studio 데이터셋 계약(`datasets/CONTRACT.md`, `kind: record`류)으로 내보내고, 판정 JSON(`studio-votes/v1`)을 에이전트가 읽어 다음 작업에 쓰기(SC2·SC5).
   - Datasette는 선택 설치(`[web]`)의 표 훑어보기용으로만.
4. 설계 v3.2의 `serve.py`·배너 플러그인·대조 canned query는 이 결론에서는 **최소 구성 밖**이 된다(사용자 결정 필요).

## 한계
- 엑셀은 화면을 캡처하지 않고 사용 기록으로 채점했다. 필요하면 computer-use로 캡처해 재채점.
- KNIME·DuckDB UI는 임시 폴더에서 실측해 채점함(2026-11-03). Power BI는 라이선스 동의가 필요해 보류.
- 임시 폴더(`%TEMP%`)는 저장소 센스의 "임시 파일 정리"가 켜져 있어 디스크 부족 때 지워질 수 있다. 화면 증거는 `gui_shots/`로 옮겨 보관.
- 사용자가 만든 UX 체크리스트 로그(UX-REFERENCE-001, `ux-checklist-log.json`)는 로컬에서 찾지 못해 반영하지 못했다. 위치를 알면 기준에 추가.
- studio 화면은 합성 데이터셋(record-demo)으로 띄웠다. 실제 데이터 화면은 보지 않았다.
