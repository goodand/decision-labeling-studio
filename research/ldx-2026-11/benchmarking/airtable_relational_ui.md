# Airtable 관계형 표 UI 벤치마킹 (2026-11-03) — studio 표 대조 화면 설계 입력

목적: decision-labeling-studio에 없는 **표 대 표 대조** 화면 종류를 만들기 전에, 관계형 표를 사람이 보기 쉽게 만든 대표 제품(Airtable)의 화면 패턴을 실측한다.

## 방법
- 대상: Airtable 공식 템플릿 "Product catalog and orders"의 **읽기 전용 공개 미리보기**(`airtable.com/embed/appB0Khlz9d6BxNhE/shrTHcv4TBVCre6mh`). 로그인·복사 없이 열림. 표 7개(Furniture, Vendors, Clients, Client orders, Order line items, Designers, Vendor contacts)가 연결 레코드로 묶여 있음.
- 화면: 앱 내장 브라우저로 직접 조작하며 캡처(`gui_shots/airtable_*.jpg`).
- 구조: REA 6.8.0(`npx` 없이 `%TEMP%\ldxg\rea`에 설치, 에이전트 설정 등록 안 함)을 전용 Edge(임시 프로필, 127.0.0.1:9333)에 붙여 `inspect-web-page`로 DOM·접근성·네트워크 관찰.
- 사용자 Chrome(로그인 상태)은 화면 제어 도구의 보기 전용 권한으로 홈 화면만 봄(베이스 없음). Claude in Chrome 확장은 연결된 브라우저 0개라 사용하지 못함.

| 패턴 | 관찰 | 우리 표 대조 화면에 가져올 것 |

| 표 탭 | 상단에 표 이름 탭, 표마다 별도 화면 | 소스·시트 선택을 탭으로 |
| 연결 레코드 칩 | 셀 안에 연결된 레코드 이름이 칩으로(`box + cask`), 여러 개면 칩 여러 개 | 대조 쌍의 상대 행을 칩으로 표시 |
| 연결 레코드 카드 | 칩을 펼치면 대상 레코드의 기본 필드 + 요약 필드 2개가 카드로 뜸, 표 이동 없음 | 다른 소스 행을 화면 이동 없이 카드로 미리보기 |
| 레코드 펼쳐 보기 | 행을 펼치면 모든 필드를 세로로, 연결 레코드는 카드로 중첩, 좌상단 ▲▼로 이전·다음 레코드 | 대조 쌍 하나를 세로 2열(A/B)로 펼치고 ▲▼로 다음 쌍 — studio record 화면의 "저장 후 다음"과 결합 |

## 구조 (REA 관찰)
- **접근성:** 그리드에 grid·row·gridcell 역할이 없음(div 1,539개 중 tab 7개만 의미 역할). 화면 읽기 프로그램·자동 검증에는 불리 → 우리는 표준 `<table>` 또는 Tabulator(ARIA 지원)로.
- **데이터 로딩:** 표 탭을 바꿀 때마다 `GET /v0.3/table/<표ID>/readData`로 **그 표만** 불러옴(문서 교체 없음). 응답은 msgpack 허용(`allowMsgpackOfResult=true`)이라 REA로 JSON 구조는 못 봄.
- **한계:** REA는 관찰 중 문서가 바뀌면 결과를 버림(새로고침 관찰 불가, 설계상 정상). 공개 미리보기라 편집·필터 저장 같은 쓰기 기능은 보지 않음.

## 우리 사례 재현 — 로그인 계정에서 직접 편집 (2026-11-03)
사용자가 앱 내장 브라우저에서 Airtable에 로그인한 뒤, 템플릿을 새 베이스 "Product catalog"(`appIDzB9bHhFnRYHr`, My First Workspace)로 복사하고 **합성 데이터**로 표 3개를 만들었다. 실제 원본 데이터는 넣지 않았고, 기존 "Untitled Base"는 건드리지 않았다.
- `사업`: (합성) 스마트공장 구축 지원 / (합성) 수출 바우처 / (합성) 패션 디자인 시제품 지원
- `DB사본`: DB측 행 2개, `사업` 연결 레코드, `type` = 내역사업·세부사업 (세션 [655] "DB에선 내역사업 type" 흉내)
- `엑셀사본`: 표 복제로 만든 엑셀측 행 2개, `type` = 세부·내역 (세션 [657] "엑셀 단위로 보면 세부" 흉내)

| 확인 | 결과 | 표 대조 화면에 주는 것 |
|---|---|---|
| 역연결 자동 생성 | 두 소스 표에서 `사업`을 연결하자 `사업` 표에 `DB사본`·`엑셀사본` 역연결 열이 자동으로 생김 | ldx가 "대응 쌍" 표 하나만 만들면 양쪽에서 탐색 가능 |
| 레코드 펼쳐 보기 | 사업 하나를 펼치면 DB측 카드(type 내역사업)와 엑셀측 카드(type 세부)가 원래 열 이름 그대로 세로로 쌓임(`gui_shots/airtable_synth_compare_expanded.jpg`) | A16 "원래 열 이름·값 그대로"를 그대로 만족 |
| **lookup 열로 나란히** | `사업` 그리드에 lookup `DB type`·`엑셀 type`을 더하자 **한 행에 두 소스의 type이 옆 열로** 나옴: 수출 바우처 = 세부사업 / 내역, 스마트공장 = 내역사업 / 세부(`gui_shots/airtable_synth_compare_grid_lookup.jpg`) | **표 대 표 대조의 핵심 형태 = "사업 1행 × 소스별 열"**. 대응 없는 사업(패션)은 빈칸으로 바로 보임 |
| 연결 고르기 | 셀의 +를 누르면 대상 표 레코드 목록·검색 상자. 필드 설정에 "AI로 상위 후보 추천", 필드 종류에 "Deep match to <표>"가 있음 | 대응 후보 추천은 확장 자리(에이전트가 만들 로직) |
| 함정 | 표를 복제한 뒤 이름을 바꿔도 **역연결 열 이름은 "DB사본 copy"로 남음**. 창 폭이 바뀌면 좌표 클릭이 엇나감 | 화면 종류 설계 때 열 이름은 표 이름에서 매번 다시 계산 |
| 입력 | 셀 더블클릭 → 입력 → Return(저장 후 아래로 이동). 한글 입력 정상 | — |

## 결론 — studio `table_compare` 최소 구성 초안
0. **기본 보기 = "사업 1행 × 소스별 열" 그리드**(Airtable lookup 재현 결과). 같은 이름의 열(예: type)을 소스별로 옆에 두고, 대응 없는 소스는 빈칸.
1. 왼쪽 쌍 목록(사업명·상태·판정 여부), 가운데 **A/B 두 소스의 행을 세로 2열로 펼친 카드**(원래 열 이름·값 그대로, 출처 파일·시트·원래 행 번호), 오른쪽 판정(같음/다름/판단불가 + 사유).
2. 다른 표에 연결된 행은 칩 → 클릭하면 카드 미리보기(화면 이동 없음).
3. ▲▼와 `#<쌍 ID>` 딥링크, 저장 후 다음 미판정 쌍.
4. 데이터는 표 단위로 지연 로드(Airtable과 같은 방식) — ldx가 쌍별 JSON을 만들고 화면은 필요한 쌍만 읽음.
5. 그리드는 Tabulator(MIT) 재사용, 셀 차이 강조는 daff(MIT) 선택 보기.
