ldx 아키텍처 v3 — 재사용 코드 + 접착 코드, 기능마다 최소 구성

의존은 위→아래 한 방향. 파란 상자 = 이미 돌아가는 남의 코드(재사용), 노란 상자 = ldx가 직접 짜는 접착 코드, 회색 점선 = 설계상 자리만 둔 확장(지금은 안 만듦). 원본(빨간 점선)은 복사·읽기만 하고 Datasette·검색·쿼리는 .ldx 안 사본만 연다.

① 사용자 접점
사람: Datasette 웹 화면 (재사용)
  • 표 보기·필터·SQL·FTS 검색, datasette-search-all로 모든 시트 검색
  • 실행: datasette -i .ldx/data/*.db (사본만)
ldx 플러그인 (접착)
  • 대조 화면 /-/ldx/compare (SC2) — register_routes 훅
  • 상단 배너: 못 읽은 파일·읽은 비율 (SC5)
에이전트: ldx CLI (typer)
  • source add · scan · show · search · compare · query · export
  • 성공 stdout JSON 1개, 실패 stderr + 종료 코드
확장 자리
  • MCP 서버, 프로파일·차트 화면
↓ 웹 플러그인과 CLI는 같은 명령 함수를 부른다
② 명령 (단일 진실: commands.py) — 모든 반환은 결과 봉투
commands.py + types.py
  • 결과 봉투 {ok, data, truncated, total_rows, limitations[], read_completeness}
  • 오류 종류·종료 코드 표 하나
확장 자리
  • total_rows_exact, jsonl·csv·table 출력
↓
③ 기능 (최소 구성)
scan (SC3·SC1)
  • 폴더 순회 → (size, mtime_ns) 바뀐 파일만
  • SQLite: 항상 사본(본체+부속 파일 복사 → 사본에서 체크포인트·journal=delete)
  • 엑셀: 바이트를 메모리로 → python-calamine → sqlite-utils로 시트별 표 + _행
  • 잠김·손상 → limitation
search (SC4)
  • SQLite FTS5 trigram (sqlite-utils enable_fts)
  • FTS 없는 표는 검색 대상에서 빼고 limitation (Datasette가 조용히 무시하므로)
  • 띄어쓰기 변이: kiwipiepy로 질의 정규화 후 재검색
compare (SC2)
  • 사업명으로 소스마다 검색 → 소스별 행을 원래 열 이름·값 그대로 나란히
  • 합치기·정규화 없음 (A16)
query (SC6)
  • Datasette validate_sql_select + 한 문장 + query_only
  • 등록된 사본만 (A05)
export (SC1·A17)
  • .ldx/exports/에 새 이름, 같은 이름 있으면 거부
  • SC7 --location-only: 셀 원문 필드 제거
확장 자리
  • 스냅샷 생략(비WAL·부속 파일 없음·안전 경로면 immutable=1 직접), 내용 해시·세대 번호(P1·P2), 자동 감시, 문자 n-gram, fuzzy, 열 대응표, 2.2GB용 증분 변환
↓ 쓰기는 .ldx 안에만 · 원본은 읽기만

.ldx/ (ldx 소유, 쓰기 허용)

  • catalog.db — sources, files(size, mtime_ns, status, 사본 경로), tables, columns
  • data/ — SQLite 사본·엑셀 변환 DB (안전한 내부 ID 파일명, #·' 없음) + FTS 표
  • exports/ · tmp/ (TMP·TEMP·cwd 지정) · logs/

원본 영역 (쓰기·새 항목 생성 금지)

  • budget_sme(두 판)·budget_all·budget2026.all .sqlite, 공고 마스터·평가셋 .xlsx, CSV
  • 접근은 파일 복사(읽기)와 바이트 읽기뿐. sqlite3·DuckDB·Datasette로 원본을 직접 열지 않는다
  • 사람은 엑셀로 자유롭게 고친다 → 다음 scan이 반영
