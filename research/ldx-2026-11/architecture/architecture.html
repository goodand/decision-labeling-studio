ldx 전체 아키텍처 v2 (MVP, 혼자 쓰는 경량 도구)

의존은 위→아래 한 방향. types.py는 의존이 없어 모든 층이 가져다 쓴다. 원본은 빨간 점선 영역이며 ldx는 이 영역에 쓰지도, 새 파일을 만들지도 않는다(원본 불변).

사람 (본인)브라우저
AI 에이전트셸에서 ldx …
↓
① 인터페이스 — 기능 로직 없음
web/ — 사람용 화면
  • localhost 전용, Origin 검사
  • 열 카드(품질·분포) + 그리드 + 전체 검색
  • 화면 기술 미정 (재사용 기능 단위 17)
cli.py — 에이전트용 (Typer)
  • 성공: stdout에 결과 봉투 JSON 하나
  • 실패: stderr {ok:false, error:{kind,message,hint}} + 종료 코드
  • source add|list|remove · scan · search · query · profile · show · doctor
↓
② 명령 계약 (commands.py) — 단일 진실
명령별 계약 + 실행 연결부
  • 이름 · 입력/출력 스키마 · 예시 · core 함수 연결
  • 부수효과 선언: writes_owned, network, launches_process (원본 쓰기 항목은 존재하지 않음)
  • 실제 강제는 AST 검사 테스트(개발 워크플로 ⑥)
↓
③ 핵심 로직 (core) — UI import 금지
catalog.py
  • 파일·테이블·열 자산, 내부 ID = 상대경로+시트 해시
  • 증분 갱신: size·mtime_ns 먼저, 바뀐 것만 sha256
  • 쓰기 연결은 명령마다 짧게, 잠기면 catalog_busy
query.py — 읽기 전용 SQL 가드
  • 문장 수 = 1
  • json_serialize_sql + CTE 내부 문장 종류 검사
  • 등록된 뷰만, 시간·행 제한, 잘림 표시
search.py
  • Retriever: BM25(Kiwi) · 문자 n-gram · Fuzzy(score_cutoff)
  • RRF 결합, 결과 없음 허용
profile.py
  • 기본 처음 1,000행 → 전체 전환
  • 표본·근사 여부 표시, unique는 정확 계산
↓ 원본에 닿는 길은 아래 두 모듈뿐
④ 어댑터 (adapters) — 원본 열기·ATTACH의 유일한 통로
sqlite.py
  • 헤더 18~19바이트로 WAL 판별
  • WAL이면 .ldx/snapshots/에 DB+WAL 복사 후 읽기
  • 아니면 Path.as_uri() + mode=ro + query_only
csv.py
  • 인코딩 지정·사용자 저장값, UTF-8 실패 시 CP949
  • 행 단위 거부 기록, 빈 파일은 empty
xlsx.py
  • bytes로 읽어 메모리 처리(핸들 즉시 닫기)
  • 시트 1개 = 테이블 1개, 표시 이름은 별도
⑤ engine.py — DuckDB 연결 소유
연결 팩토리 (모든 연결이 여기서만)
  • 설정 순서 고정: ① adapters가 만든 ATTACH 명세(원본·스냅샷, READ_ONLY)를 실행 → ② temp_directory(절대경로) → ③ enable_external_access=false → ④ autoinstall/autoload 끄기 → ⑤ lock_configuration=true
  • 조회용은 in-memory, 카탈로그는 READ_ONLY ATTACH
types.py — 의존 없음
  • 결과 봉투 {ok, data, truncated, total_rows, total_rows_exact, limitations[], read_completeness}
  • 자산 타입(파일·테이블·열)
  • 오류 종류: sql_rejected, catalog_busy, source_locked, immutability_violation …
용어 (GLOSSARY.md)
  • 결과 봉투 = 결과를 잘림·못 읽은 항목·완전성과 함께 감싼 공통 응답
  • 읽기 전용 SQL 가드 = 실행 전 읽기 외 문장 거부
  • 부수효과 선언 = 명령이 일으키는 바깥 영향의 선언

ldx 소유 저장소 — 쓰기 허용 영역

위치: ldx_workbench/.ldx/ (경로는 cwd가 아니라 패키지 위치 기준, git 제외)
catalog.duckdb · snapshots/ · index/ · tmp/ · logs/

원본 데이터 — 읽기 전용 경계 (원본 불변)

예: D:\dev_eval_team\…\*.sqlite(최대 약 2.2GB, 현재 전부 비WAL) · 공고 마스터 *.xlsx · CSV(CP949 포함)
금지: 내용 변경 · -wal/-shm/-journal · DuckDB 임시 파일 · 같은 폴더의 새 파일
등록 폴더 안의 .ldx는 스캔에서 제외(등록 거부 아님), 정션·심볼릭 링크는 따라가지 않음
인터페이스명령 계약 핵심 로직어댑터 엔진 설정 근거: adversarial_review_v1.md R01~R27, subflows.yaml
