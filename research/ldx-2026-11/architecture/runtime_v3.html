ldx 실행 흐름 v3 — 명령별 단계

파랑 = 재사용 코드가 하는 단계, 노랑 = 접착 코드, 빨강 테두리 = 실패·한계를 결과 봉투의 limitations[]로 남기는 지점. 모든 흐름의 끝은 결과 봉투 하나.

scan — 등록 폴더 갱신 (SC3·SC1, A01~A03·A08·A15)

TMP·TEMP·cwd를 .ldx/tmp로
폴더 순회, .ldx 자신은 samefile로 제외
catalog의 (size, mtime_ns)와 비교 → 바뀐·새 파일만
SQLite: 본체+-wal·-shm·-journal를 .ldx/data/<ID>로 복사 → 복사 전후 (size, mtime_ns) 같을 때만 채택 → 사본에서 체크포인트
엑셀: python-calamine(메모리 바이트) → sqlite-utils 시트별 표 + _행 + FTS5 trigram
잠김·손상·빈 파일 → status=locked/error, limitation
catalog 갱신, 봉투(read_completeness = 읽은 파일/대상 파일)

search "질의" (SC4·SC7, A12·A13)

catalog에서 대상 표 목록 (모든 시트)
FTS 없는 표 → 제외하고 limitation (조용한 전체 반환 방지)
FTS5 trigram MATCH (사본 DB, immutable=1)
0건이면 kiwipiepy로 띄어쓰기·조사 정규화 후 재검색
파일·시트·열·_행 + 셀 원문(--location-only면 제거)
한도 초과 → truncated, total_rows

compare "사업명" (SC2, A16)

search를 소스별로 호출
소스마다 일치 행의 원래 열 이름·값 그대로
소스·시트·행을 나란히 (합치기·정규화 없음)
GUI: Datasette 플러그인 화면 / CLI: JSON

query --sql (SC6, A04·A05·A09·A14)

Datasette validate_sql_select (SELECT만)
문장 수 = 1, ATTACH·load_extension 거부
위반 → sql_rejected, 종료 코드
사본 DB, immutable=1 + query_only로 실행
한도 초과 → truncated, 숫자는 봉투 값

export (SC1, A17)

대상 경로가 .ldx/exports/ 또는 원본 밖 지정 경로인지 확인
같은 이름 존재·원본 폴더 안 → 거부
sqlite-utils / openpyxl로 새 파일 쓰기
봉투에 새 파일 경로
