ldx 실행 흐름 v3.1 — 명령별 단계

파랑 = 재사용 코드, 노랑 = 접착 코드. 빨강 실선 = limitation에 기록하고 그 파일만 건너뛰어 다음으로 계속, 빨강 이중선 = 명령 중단(오류 봉투·종료 코드). 모든 흐름의 끝은 결과 봉투 하나.

scan — 바뀐 파일을 새 세대 사본으로 (SC3·SC1, A01~A03·A07·A08·A15)

cwd·TMP·TEMP = .ldx/tmp, catalog 잠금(실패면 catalog_busy)
디스크 여유 < 대상 크기×2.3 → disk_low 중단
순회(.ldx·~$*·*.tmp 제외), (size, mtime_ns, 앞뒤 64KB 해시) 비교 → 바뀐 파일만
snapshot: SQLite 복사 → 전후 stat 같을 때 채택(재시도 3회) → 사본 체크포인트
convert: calamine(엑셀) / csv(utf-8-sig→cp949) → sqlite-utils 표 + _source_row + FTS(원문·Kiwi 열)
잠김·손상·인코딩 실패·작업 중 사본 → read_status·limitation
catalog에 새 세대 기록(원자적), 봉투(read_ratio 파일·표)

serve — 사람용 화면 (SC1 반영, SC5 배너)

catalog의 현재 세대 경로만 모음 (SC7 대상 표 제외)
Datasette 프로세스 -i copies/<세대>/*.db + search-all + 배너 플러그인
scan 완료 신호 → 서버 종료 → 새 세대로 재기동(약 1.2초)
재기동 후 옛 세대 폴더 삭제(실행 중엔 Windows가 막음)

search "질의" [--positions-only] / compare "사업명" (SC4·SC7·SC2, A12·A13·A16)

catalog에서 현재 세대 표 목록, 원본 stat 재확인 → 바뀌었으면 limitation "scan 필요"
FTS 없는 표 → 제외+limitation
질의 < 3글자: LIKE / 이상: FTS5 MATCH(원문 OR Kiwi 정규화 질의) — 사본 immutable=1
파일·시트·열·_source_row + 셀 원문(positions-only면 제거), 한도 초과 → truncated
compare: 소스별 정확 일치 먼저, 부분 일치 표시, 원래 열 이름·값 그대로(합치지 않음)

query --sql (SC6, A04·A05·A09·A14)

대상이 등록·현재 세대 사본인지 catalog로 확인(아니면 not_registered)
sqlite3 연결: immutable=1, query_only, 확장 로드 끔, set_authorizer(SELECT·READ·FUNCTION)
쓰기·ATTACH·pragma·여러 문장 → sql_rejected 중단
한도 초과 → truncated, total_rows_exact(셀 수 있으면 정확, 아니면 하한)

export (SC1, A17)

대상 경로 realpath·normcase → .ldx/exports/ 안인지
밖이거나 같은 이름 존재 → 거부(중단)
sqlite-utils / csv로 .ldx/tmp에 쓰기
x 모드 새 이름으로 rename, 봉투에 경로
