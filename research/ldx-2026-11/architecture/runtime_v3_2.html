ldx 실행 흐름 v3.2 — 명령별 단계

파랑 = 재사용, 노랑 = 접착. 빨강 실선 = limitation 기록 후 그 대상만 건너뛰고 계속, 빨강 이중선 = 명령 중단(오류 봉투·종료 코드). 모든 흐름의 끝은 결과 봉투 하나.

source add (SC3, A02)

경로 realpath·normcase
원본 루트와 .ldx가 서로 포함 → source_overlap 중단
catalog에 소스 등록(짧은 트랜잭션)

scan — 바뀐 파일만 새 세대 사본 (SC3·SC1, A01~A03·A07·A08·A15)

cwd·TMP·TEMP=.ldx/tmp, scan.lock 획득(있으면 catalog_busy)
허용 확장자 순회, 부속 파일은 본체에 묶음, 시그니처(본체+-wal·-journal) 비교
~$이름 있음·잠김 → "열려 있음"/source_locked, 이전 사본 유지
디스크 < 바뀐 크기×4 + 남은 세대 → disk_low
snapshot: 부속 파일 이름 맞춰 복사, 전후 stat, 사본 복구·체크포인트·quick_check
convert: calamine/csv → sqlite-utils 표 + 원문 FTS / textindex: Kiwi 묶음 → 사이드 표
손상·인코딩 실패·빈 시트·FTS 불가 표 → limitation
catalog: 새 세대 포인터 한 트랜잭션, gc_generations(), 봉투(read_ratio·read_scope)

serve — 사람용 화면 (SC1·SC5)

catalog에서 현재 사본 경로 목록(SC7 DB 제외)
Datasette 프로세스 -i 목록 + search-all + 배너
catalog 세대 번호 폴링 → 바뀌면 종료·재기동(약 1.2초)
재기동 실패 → 이전 목록으로 재기동 + 배너 경고
gc_generations(): 참조 0인 사본만 삭제, 실패는 다음에 재시도

search "질의" [--positions-only] / compare "사업명" (SC4·SC7·SC2, A12·A13·A16)

catalog 현재 세대 표 목록 + staleness() → 바뀌었으면 "scan 필요"
FTS 없음·WITHOUT ROWID 표 → 제외+limitation
질의를 단어로 나눔 → 한글 있으면 textindex로 형태소(같은 설정)
형태소마다 [사이드 표 MATCH] OR [3글자↑ trigram / 미만 LIKE], 단어끼리 AND — 사본 mode=ro&immutable=1
사본 열기 실패 → catalog 다시 읽어 1회 재시도 → limitation
파일·시트·열·_source_row + 셀 원문(positions-only·SC7이면 제거), truncated
compare: 소스별 정확 일치 먼저, 부분 일치 표시, 원래 열 이름·값 그대로

query --source S --sql (SC6, A04·A05·A09·A14)

S가 등록된 현재 사본인지(아니면 not_registered), staleness()
sqlite3 mode=ro&immutable=1, query_only, 확장 로드 끔, authorizer(+RECURSIVE·읽기 PRAGMA)
쓰기·ATTACH·pragma 쓰기·여러 문장 → sql_rejected
시간 상한 초과 → query_timeout
SC7 표 원문 제거, truncated, total_rows_exact, snapshot_at

export (SC1, A17)

대상 realpath·normcase → .ldx/exports/ 안인지
밖이거나 같은 이름 존재 → 거부
csv(utf-8-sig)·sqlite-utils로 .ldx/tmp에 쓰기
os.rename(교체 없음)으로 새 이름, 봉투에 경로
