ldx 아키텍처 v3.1 — 판정표 v3 반영 (재사용 + 접착 코드, 기능마다 최소 구성)

의존은 위→아래 한 방향. 파랑 = 재사용 코드, 노랑 = 접착 코드, 주황 굵은 테두리(✎쓰기) = .ldx에 쓰는 기능, 회색 점선 = 확장 자리(미구현). 원본(빨간 점선)은 한 번 읽고 바로 닫는 파일 복사·바이트 읽기만. sqlite3·Datasette는 .ldx 안 사본만 연다.

① 사용자 접점
사람: Datasette 웹 (재사용, [web] 선택 설치)
  • 표 보기·필터·SQL·FTS 검색, datasette-search-all
  • 대조: canned query 화면
  • 명령 계층을 거치지 않음 → 결과 봉투·positions_only 미적용. SC7 대상 표는 올리지 않음
ldx serve + 배너 플러그인 (접착)
  • 현재 세대 사본만 -i로 Datasette 프로세스 실행
  • scan 완료 → 서버 재시작(약 1.2초) → 옛 세대 삭제
  • 배너: 못 읽은 항목·read_ratio·snapshot_at·"원본 바뀜, scan 필요"
에이전트: ldx CLI (typer)
  • source add · scan · show · search · compare · query · export · serve
  • compare 도움말 첫 줄: "나란히 보여 줌, 합치지 않음"
  • 성공 stdout JSON 1개, 실패 stderr + 종료 코드
확장 자리
  • MCP 서버
  • 대조 전용 화면(register_routes)
  • 프로파일·차트
↓ CLI와 배너 플러그인만 명령 계층을 부른다 (단일 진실의 범위 = ldx 명령)
② 명령 계층 — commands.py(진입점) + types.py(의존 없음)
결과 봉투
  • {ok, data, truncated, total_rows, total_rows_exact, limitations[], read_ratio, snapshot_at}
  • read_ratio 분모 공개: 파일 수·표 수
오류 종류·종료 코드 표 하나
  • sql_rejected · catalog_busy(retry_after_ms) · source_locked · not_registered · disk_low
확장 자리
  • jsonl·csv·table 출력 (render(envelope, fmt))

③ 기능 (최소 구성)
scan (SC3·SC1)
  • 폴더 순회, .ldx 자신·~$*·*.tmp 제외
  • (size, mtime_ns, 앞뒤 64KB 해시) 바뀐 파일만
  • snapshot → convert → catalog 순으로 호출만 함
  • 시작 전 디스크 여유 점검(원본×2.3)
snapshot.py
  • SQLite 본체+부속 파일 복사, 전후 stat 비교·재시도
  • 부속 파일 있었으면 limitation "작업 중 사본"
  • 사본에서 체크포인트·journal=delete
convert.py
  • 엑셀: python-calamine(메모리 바이트, 전후 stat)
  • CSV: utf-8-sig → cp949, 실패면 limitation
  • sqlite-utils: 시트별 표 + _source_row, 중복 열 _2
  • FTS5 trigram(원문 열 + kiwipiepy 형태소 열)
catalog.py
  • 경로·스키마·세대의 유일한 소유자
  • sources, files(size, mtime_ns, head_tail_hash, read_status, 세대), tables, columns
  • 잠기면 catalog_busy
search (SC4·SC7) + compare 함수 (SC2)
  • 질의 < 3글자: LIKE / 이상: FTS(원문·형태소 열)
  • FTS 없는 표는 제외+limitation
  • --positions-only: 셀 원문 제거
  • compare: 정확 일치 먼저, 부분 일치는 표시해 구분, 소스별 잘림·limitation 전달
query (SC6)
  • 표준 sqlite3: set_authorizer(SELECT·READ·FUNCTION만), 한 문장, query_only, 확장 로드 끔
  • 현재 세대 사본만, immutable=1
export (SC1·A17)
  • .ldx/exports/만 허용(realpath·normcase)
  • .ldx/tmp에 쓰고 x 모드로 새 이름 rename, 있으면 거부
  • sqlite-utils·csv
확장 자리
  • reader(path) -> sheets(hwpx 등)
  • 문자 n-gram, fuzzy, 열 대응표
  • 2.2GB 증분 변환, 자동 감시
↓ 쓰기는 .ldx 안에만 · 원본은 읽기만

.ldx/ (ldx 소유, 쓰기 허용, 시작 시 cwd = .ldx/tmp, TMP·TEMP도 여기)

  • catalog.db
  • copies/<세대>/<ID>.db — SQLite 사본·엑셀·CSV 변환 DB + FTS. 세대는 폴더로, 파일명 고정(점·#·' 없음)
  • exports/ · tmp/ · logs/

원본 영역 (쓰기·새 항목 생성 금지)

  • budget_sme(두 판)·budget_all·budget2026.all .sqlite, 공고 마스터·평가셋 .xlsx, CSV
  • 접근 = stat, 파일 복사, 바이트 읽기뿐 (한 번 읽고 즉시 닫음). 어떤 DB 엔진으로도 직접 열지 않는다
  • 사람은 엑셀로 자유롭게 고친다 → 다음 scan이 새 세대로 반영
재사용 코드접착 코드.ldx에 쓰는 기능확장 자리원본 영역 의존성: datasette 0.65.5([web]) · datasette-search-all · sqlite-utils · python-calamine · kiwipiepy(Apache-2.0, 지연 import) · typer — 제거: duckdb · bm25s · rapidfuzz · openpyxl
